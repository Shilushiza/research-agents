# Deep research: формализация MPC-слоя — PRSS, threshold-HE, compartmented secret sharing (2026-09-11)

## Рамка
Задача (из голосовых заметок пользователя): формализовать (1) механизм сложения N
участников при условии, что сервер не входит в число участников; (2) гомоморфное
шифрование как альтернативу/дополнение; (3) правило «знают двое — знает семья» —
корректировку модели угроз с учётом того, что роботы одного дома не являются
независимыми доверительными единицами. Контекст — MPC-слой privacy-роадмапа
проекта (see [[shamir-secret-sharing-mpc-2026-09-11]]), где уже установлено, что
голая связка Bonawitz+Shamir не покрывает byzantine- и групповую угрозу.

## Что уже известно лаборатории
Outline недоступен — не опрошено. Внутри проекта — см. `shamir-secret-sharing-mpc-2026-09-11.md`,

## Состояние области
- **PRSS (Pseudorandom Secret Sharing)** — Cramer, Damgård, Ishai, *Share Conversion,
  Pseudorandom Secret-Sharing and Applications to Secure Computation*, TCC 2005
  (Springer LNCS 3378, pp. 342–362). Позволяет из один раз распределённых PRF-ключей
  локально (без коммуникации в каждом раунде) генерировать свежие Shamir-разделения
  псевдослучайного значения — в частности, разделения нуля для маскирования. Прямой
  ответ на «механизм сложения N участников без сервера как участника»: сервер не
  получает вообще никакого ключевого материала, поскольку структура доступа и PRF-ключи
  определены только над множеством участников $P$, сервер $S \notin P$.
- **Straggler-resilient PRSS** — *Generalized Pseudorandom Secret Sharing and Efficient
  Straggler-Resilient Secure Computation*, [Springer 2021, DOI
  10.1007/978-3-030-90453-1_5]. Явно решает проблему отвалившихся участников для PRSS —
  прямая релевантность к флоту роботов с нестабильной связью (Wi-Fi).
- **Threshold Paillier / threshold homomorphic encryption** — additive HE (Paillier,
  1999) с секретным ключом расшифровки, разделённым по Shamir между $N$ участниками:
  расшифровать может только коалиция $\ge t$ участников, сервер-агрегатор не держит
  ключа вовсе, только суммирует шифротексты по гомоморфному свойству. Обзор построения
  и его безопасности — общедоступные источники по threshold Paillier (see references
  in .tex). Компромисс относительно PRSS/маскирования: вычислительная (а не
  информационно-теоретическая) безопасность, дороже по компьюту (модулярное
  возведение в степень против сложения), но не требует интерактивного попарного
  согласования ключей на каждом раунде — только конечный шаг расшифровки нуждается в
  $t$ живых участниках, не все $N$ на этапе маскирования.
- **Compartmented / multipartite secret sharing** — Simmons 1990, Brickell 1990;
  систематизация — *Secret sharing in multilevel and compartmented groups*
  [Springer, DOI 10.1007/BFb0053748]. Формализует именно ситуацию «знают двое —
  знает семья»: участники разбиты на непересекающиеся группы (compartments), для
  каждой группы $H_j$ задан свой порог $k_j$; секрет восстановим, только если из
  каждой участвующей группы набралось $\ge k_j$ членов. Прямой формальный инструмент
  для корректировки наивного плоского $(t,N)$-Shamir, который считает всех участников
  независимыми доверительными единицами, хотя роботы одного дома таковыми не
  являются (общий Wi-Fi, общий владелец, физический доступ к обоим устройствам).

## Лидерборды / SOTA
Не применимо — криптографические протоколы, не задача с метрикой качества.

## Референс-репозитории
Прямых открытых реализаций PRSS/threshold-Paillier/compartmented-SS специально под
робо-флоты не найдено в этой волне поиска; есть общие криптографические библиотеки
(упомянуты в найденных источниках как paillier-пакеты), не привязанные к проекту.

## Соседние области и перенос
- **MPC-фреймворки общего назначения** (SPDZ-семейство) используют PRSS для
  предгенерации Бивера-триплетов — тот же примитив, что здесь предлагается для
  масок; перенос почти прямой.
- **Корпоративный/organizational secret sharing** (multilevel access structures,
  Tassa 2007) — концептуально близко к compartmented, но моделирует уровни
  полномочий (иерархия), не независимые группы (семьи) — для робо-флота именно
  compartmented (группы, не уровни) — правильная модель, не hierarchical.

## Очередь идей (по цене проверки)
1. Заменить в проектном MPC-слое интерактивное попарное согласование масок
   (Bonawitz-style) на PRSS-генерацию — снижает коммуникационную нагрузку на раунд,
   не меняя гарантию приватности. Дёшево, чисто инженерная замена.
2. Формально переопределить threat model проекта: вместо флоского $(t,N)$ считать
   эффективный порог по числу независимых **домохозяйств**, не роботов — заменить
   $|S| \ge t$ на $h(S) \ge \tau$, где $h(S)$ — число домохозяйств, представленных в
   колеблющемся множестве $S$. Средняя цена — требует пересчёта параметров
   secure aggregation под compartmented-схему, но напрямую расширяет незакрытый
   byzantine/групповой гэп из отчёта по Shamir.
3. Оценить threshold-HE как альтернативу маскированию для сценария, где участники
   (роботы) часто офлайн на этапе маскирования, но собираются вместе периодически
   для decrypt-раунда — гипотетически лучше подходит для домашних роботов с
   нерегулярным расписанием работы, чем Bonawitz-style протокол.

## Открытые вопросы
- Как оценивать $k_j$ (порог внутри домохозяйства) на практике — обычно 1–3 робота
  на дом, значит $k_j$ почти всегда тривиален (1) и вся защита сводится к порогу по
  числу домохозяйств $\tau$, а не к внутригрупповому порогу — стоит ли вообще
  усложнение compartmented-схемы, или проще напрямую считать «один голос на дом»?
- Меняется ли этот анализ, если несколько роботов одного дома физически принадлежат
  РАЗНЫМ членам семьи (не полностью доверяющим друг другу) — тогда допущение «знают
  двое — знает семья» может быть неверным и наивная независимая модель ближе к
  истине для части случаев.
